# 후원담당자용 업무정리 업데이트 — 2026-10-30

## 이번 요청의 기준

사용자의 최신 결정: 후원담당자들이 금품업무를 정리하는 홈페이지다. 별도 결재권자는 필요하지 않으며, 시스템 관리자는 계정과 기준정보를 관리한다. 기존 기획서의 다단계 결재·본인 승인 금지 요구보다 이 결정이 우선한다.

이번 수정은 가상자료 검증을 완료했다. GitHub main 반영 후 image 워크플로가 성공하면 infra/server-setup.sh로 서버를 업데이트한다. 실제 서버 반영은 서버에서 업데이트 명령을 실행할 때 이루어진다.

## 바뀐 사용 흐름

| 업무 | 담당자 처리 |
|---|---|
| 후원금 직접 입력 | 시설·후원자·수납일·금액·기금 입력 → 저장·확정 → 실적 반영 |
| 통장·엑셀 반입 | 입금 후보 또는 초안 생성 → 담당자 확인 → 확정하기 |
| 후원품 수입 | 초안 저장 → 담당자 확정 → 재고 반영 |
| 후원품 배분 | 배분 초안 → 담당자 확정(예약) → 실제 출고 반영 |
| 수납 취소·입고 역거래 | 사유 입력 → 정정 확정 → 원본을 남기고 역거래 기록 |
| 출고 후 반품 | 회수·상태검사 확인 + 사유 → 담당자 정정 확정 |
| 월 마감·재개방 | 후원담당자가 점검표 확인 후 마감; 재개방 사유 필수 |
| 기존 미확정 거래 | 확정·정정 이력에서 담당자가 처리 |

직원 관리 화면은 **후원담당 / 시스템 관리자** 두 역할을 제시한다. 후원담당은 금품·배분·문서 업무를 수행하며, 관리자만 가진 계정에는 금전업무 권한을 자동 부여하지 않는다. 관리자가 입력도 해야 한다면 후원담당 역할을 함께 부여한다.

기존 계정·이력 보호를 위해 과거 역할 코드와 승인 API는 호환용으로 남겼다. 기존 계정을 임의로 후원담당으로 전환하지 않는다. 별도 승인계정을 만들거나 승인계정으로 로그인할 필요는 없다. 내부 `APPROVED` 값은 화면에서 **확정됨**으로 표시한다.

## 후원금 입력 오류와 해결

제공된 오류는 `facilityId = null`, `fundLines = []`였다. 입력 화면에서 시설 정보가 없거나 기금이 선택되지 않아 필수 자료가 누락된 경우다.

- 시설·기금이 없으면 저장폼 대신 기준정보 설정 안내를 표시한다.
- 시설은 화면에서 선택한다. 하나뿐이면 선택해 주고 여러 개면 명시적으로 고르게 한다.
- 기금도 하나뿐이면 선택한다. 지정·비지정이 함께 있으면 임의 선택하지 않는다.
- 한 기금에 전액 배분할 때 수납액이 배분액으로 자동 입력된다.
- 두 기금 배분 시 양수·중복 기금·합계를 검사한다. 오류 후에도 입력값을 유지한다.
- 직접 입력은 `/v1/money-receipts/record`에서 생성과 확정을 한 트랜잭션으로 수행한다. 재시도는 같은 idempotency key로 중복 생성을 막는다.
- 기존 승인대기 거래도 담당자가 직접 확정할 수 있다.

운영 화면에 예전 오류가 그대로 보이는지는 서버 배포 상태 확인이 필요하다. 로컬 수정이 운영 서버를 자동 변경하지는 않는다.

## 연무 업무 항목

근거: 연무 후원·봉사 업무인수인계서(2026-09-23)의 비개인 업무 분류. 원문 PDF·계좌·연락처·암호·실명은 코드에 포함하지 않았다. 자세한 원문 쪽수와 지원 범위는 `YEONMU_SETUP.md` 참조.

| 구분 | 항목 | 반영 방식 |
|---|---|---|
| 시설 | 연무사회복지관 | 관리자가 실제 소속 주체를 선택하고 검토 후 추가 |
| 기금 | 비지정후원금 / 결연후원금 | 기존 프리셋 유지, 결연 목적 확인 후 선택 적용 |
| 모금 경로 | 일시·직접, 정기, 결연, 해피빈, 사랑의 저금통, 모금함, 법인 연계, 바자회, 외부지원, 기타·미분류 | 후원금 입력 선택항목 및 목록에 저장·표시 |
| 수납방법 | 계좌이체, 현금, CMS, 카드, 기타 | 모금 경로와 별도 관리 |
| 사업·모금명 | 내부 사업명 또는 캠페인명 | 최대 100자, 선택입력 |
| 입금·증빙 관리번호 | 내부 대장·증빙의 참조번호 | 최대 100자, 계좌번호 입력 용도가 아님 |
| 업무 메모 | 지정 조건·확인 사항 | 최대 500자, 선택입력 |
| 후원품 | 품목, 단위, 수량, 창고, 유효기한, 가액 및 평가근거 | 기존 입고 항목 사용 |
| 배분 | 사업명, 대상자 ID, 물품·수량, 출고 상태 | 기존 배분 항목 사용; 후원담당에 배분 권한 추가 |

모금 경로는 회계 계정과목이나 지정후원 목적이 아니다. 바자회·외부지원은 후원금 분류가 확인된 수납만 이 화면에 기록한다. 법인/시설 소속을 자동 합치지 않는다. 운영법인 명칭·실제 창고명·품목별 단위·지정기금 목적은 확인 후 관리자 설정으로 등록한다.

‘일시·직접’, ‘기타·미분류’는 편의를 위한 공통 분류이며 기관 공식 용어라는 뜻이 아니다. 모금 경로 목록은 현재 코드 프리셋이다. 기관별 경로 편집 화면은 후속 과제다.

## 권한·정합성 보완

- 금전 조회 권한이 없는 과거 물품전용 역할에 대시보드 금전 합계·금전 미처리 건수를 반환하지 않는다.
- 확정·정정 이력과 문서 목록·생성·HTML 재출력에 금전 조회 권한 검사를 적용했다.
- 월 마감 점검표는 금전 조회 권한도 요구한다.
- 확정 API는 거래 종류별 입력 권한을 검사한다. 관리 권한만으로 거래를 확정할 수 없다.
- 입고·배분 시 선택 시설과 창고 관계를 검사한다. 배분은 로트·창고 재고 관계도 검사한다.
- 기관 격리, 마감일 검사, 음수재고 방지, 확정 기록 직접수정 방지, 감사기록은 유지한다.
- 모바일 수입표는 표 내부 가로 스크롤을 사용해 날짜·금액이 잘게 줄바꿈되지 않게 했다.

## 코드 변경 위치

- `packages/db/migrations/0009_donation_details.sql`: 모금 경로·사업명·증빙 참조 추가. 기존 행은 기타·미분류로 유지한다.
- `packages/domain/src/donationDetails.ts`: 연무 업무 모금 경로.
- `packages/db/src/services/approvals.ts`: 담당자 직접 확정·정정 및 기존 대기 정리.
- `packages/db/src/services/money.ts`: 업무 항목 저장·조회·스냅샷. 신규 항목이 없는 기존 거래의 해시는 보존한다.
- `apps/api/src/controllers.ts`: 직접 저장·확정 API 및 정정 API.
- `apps/web/app/(app)/money/`: 시설·기금 검사, 입력값 보존, 업무 항목과 저장·확정 UI.
- `tests/integration/staff-workflow.test.ts`: 단독 확정·역거래·권한·시설·재고 검사.

## 적용 및 남은 범위

GitHub Actions의 image 워크플로 성공을 확인한 후 서버에서 기존 infra/server-setup.sh 명령을 실행한다. 새 migration 적용 후 API·웹·worker를 같은 코드 버전으로 배포해야 한다. 운영 DB를 reset하거나 시연 seed를 넣지 않는다.

이번 개발은 담당자용 기록·확정 흐름과 입력항목을 완성한 것이다. 공식 기부금영수증 발급, 결연금 실제 송금, 회계전표 자동 반영, 기관 원본 서식과의 동일 출력, 희망이음 공식 업로드는 포함하지 않는다. 수납 취소는 장부 기록이며 은행 환불을 실행하지 않는다.

다음 고도화 순서: 수입목록 기간·후원자·모금경로 검색과 전체 페이지/다운로드 → 결연 지급대장 및 증빙 연결 → 기관 실제 양식 맞춤 출력 → 영수증 발급 준비자료. 현재 수입 화면은 최근 50건이며 전체 원장을 내려받는 기능은 아직 없다. 기존 12개 고도화안 중 결재권자 추가 과제는 사용하지 않는다.
