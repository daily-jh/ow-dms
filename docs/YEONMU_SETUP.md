# 연무사회복지관 업무 항목 설정

2026-10-30 · 운영 데이터 변경 전 검토용

## 확인한 근거와 범위

설치된 연무 후원·봉사 매뉴얼 플러그인의 `references/업무인수인계서_이지윤(2026).pdf`(2026-09-23, 18쪽)를 확인했다. 접근정보·계좌·후원자/수혜자 명단·직원 연락정보를 제외하고 업무 분류·서식명만 반영했다. 원본 PDF와 원문 추출자료는 이 공개 저장소에 넣지 않는다.

이것은 내부 매뉴얼의 비개인 업무 항목을 **기준정보 설정 후보에 연결**한 것이다. 문서를 지속 동기화하거나 CMS·희망이음·실제 계좌를 자동 연결한 기능은 아니다. 내부 관행을 법정 기준으로 확정하지 않는다.

## 관리자 적용 방법

1. **기준정보 → 법인·시설**에서 실제 회계 소속 주체를 등록한다. 운영법인 이름과 고유번호를 임의 생성하지 않는다. 이미 등록되어 있으면 재사용한다.
2. **연무사회복지관 기본 항목 설정**에서 소속 주체를 선택한다.
3. 비지정후원금은 기본 선택 후보이며, 결연후원금은 필요한 경우 선택한다. 실제 기탁조건이 더 구체적이면 체크하지 말고 아래 기금 등록에서 실제 목적별 기금을 만든다.
4. 소속·기금 목적을 검토한 뒤 확인란을 체크하고 **선택한 기본 항목 추가**를 누른다.
5. 시설 `연무사회복지관`과 선택한 기금이 목록에 있는지 확인한다. 후원금 화면에서 시설·기금을 선택하고 실제 수납 근거가 있는 거래만 입력한다.

기존 값과 동일하면 재사용하며, 지정조건·목적·소속이 다르거나 사용 중지된 항목은 오류를 표시한다. 기존값 덮어쓰기·자동 재활성화는 하지 않는다. 처리 중 충돌하면 전체 트랜잭션을 롤백한다. 같은 기관에서 동시 실행해도 프리셋 적용 잠금으로 중복을 막는다. 감사기록은 `master.preset.apply`로 남는다.

설정 후보는 관리자 화면에서만 제공한다. 후원담당 역할만으로 설정을 적용할 수 없고 타 기관 법인을 선택할 수도 없다. 원장·샘플 입금·품목/재고·계좌·직원/후원자/수혜자·세무발급은 생성하지 않는다. 신규 DB migration은 없다.

## 후원금 저장 오류 수정

기존 화면은 첫 시설 ID를 숨은 입력값으로 보냈다. 신규 기관의 시설 목록이 비어 있으면 `facilityId=null`이 전송됐고, 기금·배분액을 비워도 제출되어 `fundLines=[]` 오류가 났다.

- 사용 중인 시설·기금이 없으면 저장폼 대신 기준정보 안내를 표시한다.
- 시설을 눈에 보이는 필수 선택값으로 변경한다. 하나이면 미리 표시하고, 여러 개면 담당자가 고른다.
- 기금은 담당자가 명시적으로 선택한다. 한 기금 전액배분은 수납액을 자동 입력한다.
- 두 기금 분할은 별도 선택으로 열고, 부분입력·동일 기금·금액형식·합계를 서버 액션에서 먼저 검사한다. 실제 API/서비스 검증도 유지한다.
- 검증 실패 후 입력한 금액·시설·기금·후원자·약정값을 유지한다. 성공 후에는 이전 오류와 입력을 초기화하고 목록을 갱신한다.
- 조회 전용 직무에는 저장·승인요청·취소 입력을 표시하지 않는다. API 권한·RLS는 유지한다.

## 미지원·제한

소식지 제작·결연금 송금·모금함 회수·외부지원 신청·기관 법정서식은 이번 수정에서 완성한 업무모듈이 아니다. 설정 화면에 지원범위와 추가 검증 항목을 표시한다. 실제 계좌·비밀번호·CMS 식별값·문서 속 수치를 코드나 기본값으로 옮기지 않는다.

운영 반영은 코드 검토·병합·이미지 갱신 후 진행한다. 이번 검증은 로컬 PostgreSQL과 합성자료만 사용했으며 운영 기관의 설정을 원격 변경하지 않았다.
